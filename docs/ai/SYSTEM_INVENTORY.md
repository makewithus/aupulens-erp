| Baseline pass/fail | See `docs/ai/BASELINE_FAILURES.md`. |

|---|---|

## Conventions (see `docs/_context/CONVENTIONS.md` for full detail — summarized here for what governs new AI code)

- Every API route: `auth()` → check `session?.user?.tenantId` → `await connectDB()` → inline `tenantId` filter on every query. No DI framework; no service-locator pattern; plain ES module imports throughout.
- Response shape: `{ success: true, data }` or `{ success: false, message }`. HTTP 200/201/400/401/403/404/409/500.
- Models: PascalCase file/model names, `I`-prefixed interfaces, `{ timestamps: true }`, hot-reload-safe export (`mongoose.models.X || mongoose.model(...)`), **every unique index must be compound with `tenantId`** (violations exist and are documented as known pre-existing issues, not license to repeat the mistake).
- All status/enum values come from the single 1899-line `lib/constants/statuses.ts` — never hard-coded strings. New AI-specific enums (autonomy level, workflow status, finding severity, etc.) belong there too, following the existing `*_VALUES` / `*_TRANSITIONS` / `isValid*Transition()` / `*_LABELS` / `*_COLORS` export shape.
- Multi-tenancy: subdomain → `middleware.ts` sets `x-tenant-id` header → JWT session carries `tenantId` → every query filters by it. The AI runtime's context service must enforce this at the source (Part 2.2's rule) exactly the way every existing route already does — inline, not via a removed abstraction (`lib/tenant-db.ts` was deliberately deleted in Phase 2 cleanup and must **not** be recreated, per `docs/_context/CONVENTIONS.md`).
- Naming: kebab-case API folders, camelCase `lib/` utility files, PascalCase components.

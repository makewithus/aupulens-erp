### Cross-tenant hostile-input check (specifically requested)

**Checked; no defect found.** AI-23's event payload carries only `period`/`periodStart`/`periodEnd` (strings) — no subject-record id. `extract()`'s `JournalEntry.find({tenantId: ctx.tenantId, ...})` is tenant-scoped directly; `act()`'s tool call (`score_journal_risk`, `{tenantId, entryId}`) passes `entryId` values that came only from that same tenant-scoped query, never from the payload, and `buildAndScoreJournalRisk()` itself re-scopes with `JournalEntry.findOne({tenantId, _id: entryId})` — doubly tenant-checked. New test **"C.4 cross-tenant"** confirms this concretely: tenant A's run, given a hostile `tenantId: OTHER_TENANT` embedded directly in the payload (which `observe()` never reads), scans exactly 1 journal (its own), never tenant B's ₹9,000,000 entry. Passed.

## Adversarial pass (Part C.6) — detailed

**Question asked**: what input makes AI-14 produce a confidently-wrong-*looking* (i.e., falsely reassuring) explanation a human would accept without digging further? **Answer**: a large bill and a large, same-period, same-counterparty credit note that mostly offset each other. New test posts a ₹100,000 bill and a ₹99,200 credit note in the same period for the same vendor — the reported net variance (-₹200, immaterial) is confirmed to be the true, honest net, not a fabricated partial figure (verified: `Math.abs(row.variance) < 1000` and `materialityVerdict === "immaterial"`). **This is correct behaviour, not a bug**: AI-14 is a net-movement flux analysis by construction (the same convention a standard variance report uses), and reporting the true net (-200) rather than either gross figure is the right answer to "what changed." The honest limitation, documented rather than silently accepted: **AI-14 is silent on gross same-period activity for a counterparty whose net stayed small** — ₹199,200 of real gross AR/AP-adjacent activity occurred and produced no finding at all, because the *net* fell below materiality. This is a real, structural property worth naming (a bill-and-immediate-credit-note pattern used to obscure activity from a variance-only review would not be caught by AI-14 alone — AI-27's duplicate/pattern detection and AI-15's own detectors are the layers that would need to catch this shape, not AI-14, which was never designed to). Not fixed in this pass — changing AI-14's scope from "net movement" to "gross activity" would be a product decision, not a defect.

## 9. Bugs found and fixed

1. **Missing/malformed `period` in the event payload crashed with an uncaught Mongoose cast exception, reachable through the real "explain_margin" chat intent.** `resolveWorkflowIntentCheap()` (`lib/aiRuntime/nl/resolveIntent.ts:44`) always returns `parameters: {}` for a keyword-table match, and the "explain_margin" entry (`workflowIntentMap.ts:26-32`, matching "why is gross margin down?" — the exact utterance in the brief's own D.3 dialogue 4) maps to AI-14. `handleWorkflowIntent()` passes that empty object straight through with no default. Before the fix, `observe()` did `String(event.payload.period)` → the literal string `"undefined"` → `monthBounds("undefined")` computed `Date.UTC(NaN, NaN, ...)` → an Invalid Date → an **uncaught** `CastError` from Mongoose ("Cast to date failed for value \"Invalid Date\"...") thrown all the way through `runWorkflow()` → `handleWorkflowIntent()` → the `/api/ai/command` route's top-level catch, which returns that raw internal error string to the chat user as an HTTP 500 (`app/api/ai/command/route.ts:168-170`) — a real, user-facing product bug on an ordinary, documented conversational path, not a synthetic edge case. Reproduced directly before the fix via a standalone script (`runWorkflow(ai14FluxAnalysis, {payload: {}})` threw `Cast to date failed for value "Invalid Date" ... at path "header.date"`). **Root-cause fix**: `observe()` now validates `event.payload.period` against `/^\d{4}-(0[1-9]|1[0-2])$/` and defaults to the current calendar month (UTC) when missing or malformed — the correct, non-invented interpretation of "why is margin down?" with no period stated, and the executor's own trace/audit trail already records exactly which period was actually analysed (never a silent substitution — `entityId` and `AiDecisionTrace` both carry the resolved period). `periodEnd` is now derived from the resolved period via `monthBounds()` rather than trusted as a second, independently-malformed field. **Regression tests** (`tests/ai/aiRuntime/ai14FluxAnalysisEdgeCases.test.ts`): "bug regression: the real 'explain_margin' chat path (empty parameters) resolves to the current period instead of crashing" (calls the real `handleWorkflowIntent()`, the exact real path) and "bug regression: a malformed period string ('undefined', 'not-a-period', '2026-13', '2026', '') also degrades to the current period instead of crashing". Both pass; the existing golden dataset and unit suite remain green. **Class check, and fixed in a sibling too**: the identical payload shape (`period.horizon.reached`, `String(event.payload.period)`) exists in AI-25 (`lib/aiRuntime/workflows/ai-25-working-capital-intelligence/index.ts`), reproduced and fixed identically in this same pass — see AI-25's own verification record §9. Both AI-14 and AI-25 are in this task's own scope, so both were fixed directly. **Flagged, not fixed** (out of this chunk's scope — only AI-14/AI-15/AI-16/AI-25's own files may be touched): the same `String(event.payload.period)`-with-no-validation shape plausibly exists in every other `period.horizon.reached`-consuming workflow (AI-11, AI-12, AI-13, AI-17, AI-18, AI-19, AI-20, AI-21, AI-22, AI-23, AI-24, AI-28, AI-29) — none of these were read or tested in this pass, so this is a **named suspicion for the requester to check, not a confirmed finding** for those workflows specifically.

## 9. Bugs found and fixed

1. **Cross-tenant hostile input — checked specifically per this chunk's mandate, no defect found.**
   `observe()` computes `entityId: event.tenantId` directly and never reads any record id out of
   the event payload at all — `bill.created`/`invoice.created`/`expense.submitted` all carry no
   `{model, recordId}`-shaped payload AI-27 trusts for a subsequent fetch. Every detector function
   (`findBillDuplicateCandidates(tenantId)`, `findExpenseDuplicateCandidates(tenantId)`,
   `findBankPaymentDuplicatePatterns(tenantId)`, `findDuplicatePaymentPostings(tenantId)`,
   `findDuplicateEntities(tenantId, ...)` reused from AI-19) takes only the trusted `ctx.tenantId`
   and queries with it inline — confirmed by direct code reading and by a full grep of every
   `findById`/`findOne(` call in `lib/aiRuntime/duplicates/detect.ts`
   (`Invoice.findOne({_id: billId, tenantId, ...})` at line 326 is the only such call, and it is
   already tenant-scoped). **New test added anyway** (section 4, C.4) to prove this in behaviour:
   two tenants with an identical duplicate-shaped bill pattern never cross-contaminate. AI-27 does
   **not** have the AI-01/02/03/04/07/08/09/10 defect shape — there is no externally-supplied
   record id anywhere in its trigger path to inject.

2. **`place_hold` race condition — same class as AI-19's (section 9, item 3).**
   `lib/aiRuntime/workflows/ai-27-duplicate-detection/index.ts::act()` called the shared
   `place_hold` tool from two call sites (the certain/probable candidates loop, and the
   duplicate-payments loop) with **no** `idempotencyKey` — the same missing-protection shape found
   in AI-19, exposing `placeHoldHandler`'s bare findOne-then-create race to a genuinely concurrent
   duplicate event (two overlapping `bill.created`/`ai.sweep.hourly` runs finding the same
   duplicate candidate). **Root-cause fix**: added `idempotencyKey: "ai27-hold:Invoice:${...}"` to
   both call sites (keyed on `duplicateRef` and `billId` respectively). **Regression test**:
   `ai27WorkflowEdgeCases.test.ts` › `"concurrent duplicate event: two genuinely simultaneous
   sweeps finding the same duplicate bill place exactly one hold"`. **Same class**: found in AI-19
   first, fixed identically in both workflows in this same pass (see AI-19.md section 9, item 3).
   **Not fixed** (out of this chunk's scope): the underlying race in `placeHoldHandler` itself, in
   the shared `lib/aiRuntime/tools/masterDataTools.ts` — reported for that file's owner; a unique
   partial index on `{tenantId, "subjectRef.model", "subjectRef.id", status: "open"}` would close
   this structurally for every future caller.

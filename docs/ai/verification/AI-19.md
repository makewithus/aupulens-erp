## 9. Bugs found and fixed

1. **Cross-tenant hostile input — checked specifically per this chunk's mandate, no defect found.**
   `extract()`'s `record_change` branch passes through `observed.raw.model`/`.recordId` from the
   event payload untouched (no DB read in `extract()` itself). The actual fetch happens in `act()`:
   `Model.findOne({ _id: extracted.recordId, tenantId })` — already scoped to `ctx.tenantId` inline,
   confirmed by direct code reading, not assumed. `snapshotAndDiff()` (`lib/aiRuntime/masterData/
   snapshot.ts`) never independently re-queries the core model — it only reads/writes its own
   `AiMasterDataSnapshot` collection, always `tenantId`-scoped. A full grep of every
   `findById`/`findOne(` call across `lib/aiRuntime/masterData/*.ts` confirmed every query is
   tenant-scoped. **New test added anyway** (section 4, C.4) to prove this in behaviour, not just
   in source review — passes clean. AI-19 does **not** have the AI-01/02/03/04/07/08/09/10 defect
   shape.

2. **Item-duplicate findings cited the wrong subject model** —
   `lib/aiRuntime/workflows/ai-19-master-data/index.ts`'s `reason()` (sweep mode) merged
   `vendorDuplicates`/`customerDuplicates` (real `Customer` ids) and `itemDuplicates` (real
   `InventoryItem` ids, from `findDuplicateItems()`) into one untagged `allDuplicates` array, then
   hardcoded `subjectRefs: [{ model: "Customer", id: d.aId }, { model: "Customer", id: d.bId }]` for
   every entry — meaning every item-duplicate finding pointed at an `InventoryItem` id under the
   `Customer` model, which any consumer resolving that reference (a UI drill-down, AI-18's decision
   trace, evidence citation) would fail to find. **Root-cause fix**: each source array is now
   tagged with its real model (`subjectModel: "Customer"` vs. `"InventoryItem"`) before merging,
   and the finding uses `d.subjectModel` instead of a hardcoded string. **Regression test**:
   `ai19WorkflowEdgeCases.test.ts` › `"bug regression: a duplicate InventoryItem finding's
   subjectRefs cite InventoryItem, not Customer"`. **Same class checked**: this is specific to
   AI-19's own array-merging pattern in `reason()`; no other of the 29 workflows merges
   heterogeneous-model result arrays into one finding loop with a single hardcoded model string
   (confirmed by reading every other workflow's `reason()` for a similar `[...a, ...b, ...c]` merge
   followed by a fixed `subjectRefs` model — none found).

3. **`place_hold` race condition — no `idempotencyKey` supplied, exposing the tool's own
   findOne-then-create race.** `lib/aiRuntime/tools/masterDataTools.ts::placeHoldHandler` checks
   for an existing open hold, then creates one, with no unique index on `{tenantId, subjectRef,
   status: "open"}` (only a plain compound index) — a genuinely concurrent duplicate event (no
   `event.id` to dedup on) can race both calls past the `findOne` check, creating two open `AiHold`
   rows for the same subject. AI-19's own `act()` called `place_hold` with **no** `idempotencyKey`
   at all, so the generic protection this system already built (`callTool()`'s persistent
   idempotency lock, `AiToolCall`'s unique `{tenantId, toolName, idempotencyKey}` index) was never
   engaged here. **Root-cause fix, kept inside AI-19's own source** (the shared tool file itself is
   out of this chunk's edit scope, per the task's own constraints — flagged below): added
   `idempotencyKey: "ai19-hold:${extracted.model}:${extracted.recordId}"` to the `place_hold` call
   site. **Regression test**: `ai19WorkflowEdgeCases.test.ts` › `"concurrent duplicate event: two
   genuinely simultaneous master_data.changed runs for the same bank change place exactly one
   hold"` — two truly concurrent runs via `Promise.allSettled`, asserts exactly one open hold.
   **Same class flagged for AI-27**: AI-27 calls the identical `place_hold` tool from its own `act()`
   with the same missing-idempotency-key shape — found and fixed in the same pass (see AI-27.md
   section 9). **Not fixed** (out of this chunk's scope): the underlying race in
   `placeHoldHandler` itself remains unprotected for any *other* future caller of `place_hold` that
   doesn't supply an idempotencyKey — reported here for whoever owns `lib/aiRuntime/tools/*.ts`,
   since a unique index on `{tenantId, "subjectRef.model", "subjectRef.id", status}` (partial, on
   `status: "open"`) would close this structurally for every caller at once, rather than requiring
   every future workflow to remember to pass a key.

4. **Masked-string collision hides a real bank-account change.** `maskValue()`
   (`lib/aiRuntime/masterData/masking.ts`) keeps only the last four characters of any value — two
   *different* raw values of the same length sharing the same last four characters (e.g. two
   different 12-digit account numbers both ending "2222") mask to the **identical** display string.
   `snapshotAndDiff()` (`lib/aiRuntime/masterData/snapshot.ts`) compared the masked strings
   directly (`oldMasked !== newMasked`), so this exact scenario — a genuine fraud-relevant bank
   account swap — would be silently reported as "no change," defeating the single most
   safety-critical guarantee this workflow makes ("bank detail changed → CRITICAL alert → hold").
   This is the C.6 adversarial finding: a confidently wrong *silence* is worse than a confidently
   wrong finding, because nothing ever gets investigated. **Root-cause fix**: `snapshotAndDiff` now
   also computes and stores a one-way SHA-256 hash of each field's raw value
   (`AiMasterDataSnapshot.fieldHashes`, additive/optional field) and diffs on the hash, never the
   masked string — a hash is not an unmasked value, so this does not weaken the existing masking
   rule; `fields` (masked) is retained purely for display. Snapshots taken before this fix have no
   stored hash and fall back to the old masked-string comparison for those specific rows only, so
   no historical data is invalidated. **Regression test**: `ai19WorkflowEdgeCases.test.ts` › `"bug
   regression / adversarial: a bank account number changed to a DIFFERENT number sharing the same
   length and last 4 digits is still detected"`. **Same class checked**: `maskValue()` is used
   nowhere else in the codebase outside `lib/aiRuntime/masterData/snapshot.ts` (confirmed by grep)
   — this defect shape is contained to AI-19.

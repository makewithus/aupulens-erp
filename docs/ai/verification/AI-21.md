## 9. Bugs found and fixed

**Ground truth investigated first, per this chunk's explicit instruction.** The adversarial test
(`tests/ai/aiRuntime/ai21StatementIntelligenceEdgeCases.test.ts` › `"adversarial: balance sheet
balances in total ... while a material control line is unsupported underneath"`) was failing on
arrival: `envelope.findings.find((f) => f.title.includes("Unsupported material line"))` returned
`undefined` at line 161.

**Investigation.** The fixture seeded an AP control account (`liability_payable`) with an
`AiDecisionTrace` marking it `materialityVerdict: "material"`, and a journal entry (`JE-B`) posting
₹500 debit and ₹500 credit **to the same control account** (intended to make the account "appear in
the report" while keeping the overall balance sheet balanced). Reading `annotateStatement()`'s real
detection logic (`unsupportedMaterial = materiality === "material" && reconciliationStatus ===
"unreconciled"`) against `lib/aiRuntime/reconciliation/definitions.ts`'s `ap_control` definition
(`difference = rightTotal (GL balance) - leftTotal (open AP subledger invoices)`,
`classifyReconciliationStatus()` returning `"unreconciled"` only when that difference exceeds
tolerance or an unexplained difference exists) revealed the fixture's actual numbers: **zero open
AP invoices** (`leftTotal = 0`) and a GL balance that nets to **zero** on the control account
(`JE-B`'s debit ₹500 and credit ₹500 cancel each other on the same account, `rightTotal = 0`). With
`difference = 0 - 0 = 0`, the `ap_control` reconciliation legitimately, correctly returns
`"reconciled"` — not `"unreconciled"`. **The fixture never actually created the condition it claimed
to test.** This is `matchPair`-adjacent shape (b) from the brief's own framing ruled out — it is
squarely (a), a fixture bug: the workflow's detection logic was never exercised against a real
mismatch, so its correctness was never actually in question.

**Fix.** Corrected the fixture (`JE-B`) to create a genuine GL-vs-subledger mismatch while
preserving the "aggregate balance sheet still balances" property the test is named for: `JE-B` now
debits **cash** (asset) ₹5,000 and credits the **AP control account** (liability) ₹5,000, with
**zero** open AP invoices still seeded. This produces `rightTotal (GL) = 5,000` vs.
`leftTotal (subledger) = 0` → `difference = 5,000`, `abs(difference) > tolerance (0.01)` →
`classifyReconciliationStatus()` correctly returns `"unreconciled"` — a real, machine-detected
tie-out failure (GL says ₹5,000 payable; the AP subledger shows nothing behind it) — while the
overall balance sheet remains balanced (asset total ₹15,000 = liability ₹5,000 + equity ₹10,000,
same aggregate-looks-fine shape the test's title describes). **No change was made to the workflow's
source code** — `lib/aiRuntime/workflows/ai-21-statement-intelligence/index.ts` and
`lib/aiRuntime/statements/annotateStatement.ts` were read in full and found correct as written; only
`tests/ai/aiRuntime/ai21StatementIntelligenceEdgeCases.test.ts`'s fixture was changed. Re-run: all
5 tests in that file now pass, including this one.

**This was not a case of weakening the assertion to force a pass** — the assertion
(`expect(unsupported).toBeDefined()`) is unchanged; only the fixture's seeded data was corrected to
actually trigger the condition the assertion checks for.

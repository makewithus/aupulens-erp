## 9. Bugs found and fixed

1. **Cross-tenant data leak via unscoped `findById`** — `index.ts` (`extract()`, was line 136) used `BankStatement.findById(bankStatementId)` with no `tenantId` filter (same class as AI-01/AI-02, see AI-01.md §9). `ai.sweep.hourly`'s own `observe()` already tenant-scopes its statement list, but `bank.transaction.imported`'s `bankStatementId` comes straight from the event payload — a hostile/malformed payload referencing another tenant's statement would be read (and, at EXECUTE autonomy, reconciled) cross-tenant. **Root-cause fix**: scoped to `{ _id, tenantId: ctx.tenantId }`. **Regression test**: `ai03BankReconciliationEdgeCases.test.ts`, "C.4 cross-tenant hostile input."
2. **Unbounded/unsorted candidate query risked missing real matches at scale** — `matcher.ts::findExactMatches` queried up to 200 posted `JournalEntry` documents on the bank account with **no date filter and no sort**. For any tenant with more than 200 posted entries ever on that account, MongoDB's natural (insertion) order means the 200 returned are effectively arbitrary with respect to the bank line's own date — a genuinely-matching entry could be silently crowded out by older, irrelevant entries filling the cap, producing "Unmatched bank line" for a line that should have auto-reconciled. **Root-cause fix**: added a `header.date` range filter (the same `DATE_WINDOW_DAYS` window already used for post-filtering) plus a sort, before the `.limit(200)` — so the cap now applies to the relevant window instead of an arbitrary historical slice. **Regression test**: `ai03BankReconciliationEdgeCases.test.ts`, "C.1 large volume" (250 old irrelevant entries seeded first, confirms the real match still reconciles). Also hardened `classifyUnresolvedLine`'s `BankStatement.find()` scan (previously fully unbounded, no `.limit()` at all) with a defensive `.limit(2000)` cap, same rationale, lower real-world risk since one `BankStatement` document is a whole imported batch (many lines), not one line.
3. **Adversarial confidently-wrong-answer: a Customer receipt could be mis-explained as an internal transfer** — `matcher.ts::classifyUnresolvedLine` checked the amount/date-coincidence internal-transfer heuristic **before** checking whether the bank line carried a Customer `partnerId`. A line carrying a `partnerId` is, by definition, an external receipt — never a transfer between the tenant's own accounts — but a coincidental amount+date match against an unrelated line on another statement would have silently classified it `internal_transfer` instead of escalating `unknown_ar_side`, directly contradicting this workflow's own A.1 scope rule ("never guessed at"). **Root-cause fix**: moved the `partnerId` check first, so it can never be shadowed by an amount/date coincidence. **Regression test**: `ai03BankReconciliationEdgeCases.test.ts`, "C.6 adversarial."

Class-wide flag (repeated from AI-01.md for completeness): the unscoped-`findById` cross-tenant shape (bug 1) was found identically in AI-01 and AI-02 in this same pass — **flagged for a check across the other 27 workflows**, not fixed beyond these three.

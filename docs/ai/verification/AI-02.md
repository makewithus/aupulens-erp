## 5. Failure paths

- **Nothing configured (no rule, no history, gated model)**: proposes nothing, confidence 0, zero findings — never guesses. `index.ts:263-271`, `297-305`; golden case `expense-no-rule-no-history-silent`.
- **Kill switch off / permission denied**: `act()`'s try/catch (`index.ts:369-388`) falls back to propose-only on any `set_draft_account` failure — no partial write, no throw into the business route.
- **Locked period / already-posted record**: same try/catch path — `set_draft_account`'s own tool-level checks reject a non-draft record; caught, propose-only.
- **Model unavailable**: `callLlmForReasoning`'s `gated` branch (`index.ts:297-305`) proposes nothing rather than guessing; exercised by the existing gated-model unit test.
- **Model returns nonsense (invalid account id, wrong shape)**: deterministically rejected — `isValid` check against the pre-filtered candidate set (`index.ts:310-319`); exercised by "a control account is never auto-selected."
- **Malformed source data**: the new null/missing-fields edge case (§4) confirms a structurally-present-but-empty `invoiceLines[0]` degrades cleanly rather than throwing.

## 9. Bugs found and fixed

1. **Cross-tenant data leak via unscoped `findById`** — `index.ts` (`extract()`, was lines 148/161) used `Invoice.findById(recordId)` and `Expense.findById(recordId)` with no `tenantId` filter — the same shape found in AI-01 and AI-03 (see AI-01.md §9 for the class-wide flag). A hostile/malformed `bill.created`/`invoice.created`/`expense.submitted` event referencing another tenant's record would be read cross-tenant, and at EXECUTE autonomy would WRITE `accountId` onto that other tenant's record. **Root-cause fix**: scoped both queries to `{ _id, tenantId: ctx.tenantId }`. **Regression test**: `ai02LedgerClassificationEdgeCases.test.ts`, "C.4 cross-tenant hostile input" — a tenant-B Invoice referenced from a tenant-A event now throws `"not found"` (escalates via the executor's failure path) instead of being read and classified.

No other AI-02-specific root-cause bug was found in this pass; the "class, not incident" cross-tenant finding is reported once, in AI-01.md, to avoid triplicating the same flag across all three records.

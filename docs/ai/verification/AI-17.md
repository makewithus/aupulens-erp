## 9. Bugs found and fixed

1. **Unvalidated `period.horizon.reached` payload could throw an uncaught `RangeError`, not just fail silently — reproduced and confirmed fixed, not assumed.** The source fix was already present in `index.ts` at the start of this pass (`PERIOD_PATTERN` validation, falling back to the current calendar month), but **no test existed to prove it actually works**, per the task's own instruction not to trust the unvalidated diff. Read the exact failure path this class produces for AI-17 specifically (documented in `index.ts`'s own comment, confirmed by tracing `computeReadiness.ts`): a malformed-but-present period string (e.g. `"garbage"`) reaches `periodEndOf()`'s `period.split("-").map(Number)` as `NaN`, producing an `Invalid Date` `deadline`. That alone doesn't throw — no Mongoose Date-typed query uses it, `AiTaxTransaction` is queried by the string `periodKey` — but with a real obligation configured and zero tax rows for that bogus period (`readiness: "not_started"`, which does **not** `continue` past the finding-building loop), `index.ts`'s own `reason()` unconditionally calls `o.deadline.toISOString().slice(0, 10)` for every non-`"ready"` obligation — `Invalid Date.toISOString()` throws a `RangeError`, an uncaught exception reachable on any tenant with a compliance profile configured. **Regression tests added** (`ai17ComplianceReadinessEdgeCases.test.ts`): "bug regression: a missing or malformed period.horizon.reached payload degrades to the current period instead of throwing a RangeError..." (8 malformed payload shapes through the real `runWorkflow()`, with a real obligation configured so the vulnerable code path is actually reached — an empty profile would short-circuit before ever getting there) and a direct-reproduction test calling `computeComplianceReadiness()` itself with a garbage period string. Both pass. **Class check**: this exact shape (validated in this same pass) was independently confirmed already fixed and now tested for AI-29 and AI-18 too (this task's own scope); the brief's AI-14 record separately flags the same shape as an unconfirmed suspicion across the other `period.horizon.reached` consumers outside this task's scope (AI-11, AI-13, AI-19-24, AI-28) — not re-checked here.

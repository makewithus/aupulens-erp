## 9. Bugs found and fixed

1. **A real N+1 performance defect: `extract()` called `evaluateCutoff()` once per candidate bill, sequentially, in a `for...of` loop.** Root cause: `evaluateCutoff()` (`lib/aiRuntime/cutoff/evaluateCutoff.ts`, shared verbatim with AI-14) itself does 3 sequential DB round trips per call (a redundant `Invoice.findOne` re-fetch of a document `extract()` already has, a `PurchaseOrder.findOne`, a `StockMove.find`) — calling it one bill at a time made this workflow's own wall-clock scale linearly with population size. **Measured before the fix**: 2,000 candidates took ~26s (extrapolates to ~130s at 10k) — well past the `<10s` budget (Part E.3). **Root-cause fix, within this workflow's own scope**: `extract()` now evaluates candidates in bounded-concurrency batches of 50 (`Promise.all` per batch) instead of one at a time, so wall-clock is bound by round-trip latency divided by batch width rather than candidate count. **Regression test**: `ai28CutoffIntelligenceEdgeCases.test.ts` › "C.1 large volume" — 2,000 candidates now resolve in 8.97-13.5s (vs. ~26s before), and every candidate is still correctly flagged (`exceptions` array has exactly `N` entries, no bill dropped). **Measured after the fix at the real 10k scale** (not extrapolated): 45.8s and 59.9s across two runs — a genuine ~2.5x improvement, but **the fix does not fully clear the budget at this extreme population**: the remaining bottleneck is the 3 sequential round trips *inside* `evaluateCutoff.ts` itself, which no amount of batching at AI-28's call site can collapse further — that file is shared verbatim with AI-14 and is out of this pass's edit scope. **Flagged, not fixed**: AI-14's own call site has the identical per-candidate sequential-call shape and should be checked in AI-14's own verification pass (already completed in an earlier batch — worth a follow-up re-check specifically for this N+1 characteristic, which was not the focus of that earlier pass). **Not a correctness bug** — every result was correct throughout, including at 10k; this is purely a latency/scale finding.
2. **Cross-tenant unscoped-lookup class (Defect Class 1): checked specifically, no defect found.** See the dedicated section under §4. AI-28's payload carries no subject-record id for the class to attach to; confirmed with a positive-proof test.
3. **Unvalidated `period.horizon.reached` payload (Defect Class 2): already fixed in a prior pass, validated in this one.** `observe()`'s `isValidIsoInstant()` guard was read directly (not assumed) and confirmed to default a missing/malformed `periodEnd` to the current period-end. The pre-existing test `ai28CutoffIntelligenceEdgeCases.test.ts` › "bug regression" (confirmed passing before this session, re-confirmed passing now) exercises `undefined`, `"not-a-date"`, `""`, `"2026-13-40"`, `"NaN"` — none fail the run.

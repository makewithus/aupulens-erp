## 9. Bugs found and fixed

**Unvalidated `period.horizon.reached` payload — a real, uncaught crash bug, found on the final
consolidation pass across all 30 workflows using this event key.** This record originally reported
"no bug found" (below, kept for the record) after checking tenant scoping, null-handling, and
precision/rounding — but did not check this specific path at the time, because 11 sibling
workflows (AI-13/14/17/18/21/22/23/24/25/28/29) had already been fixed for the exact same shape and
AI-12 was assumed (wrongly) to have no date logic of its own to be vulnerable. `observe()` did
`String(event.payload.periodEnd)` with **no validation at all** — not even a truthy check — so a
missing or malformed `periodEnd` produced the literal string `"undefined"` → `new Date("undefined")`
(an Invalid Date) → `extract()`'s `periodEnd` field → `act()`'s unconditional `.toISOString()`
call, throwing an uncaught `RangeError: Invalid time value` on every affected tenant's run.
**Root-cause fix**: `observe()` now validates `period`'s own shape (`PERIOD_PATTERN`) and always
DERIVES `periodEnd` from the validated period rather than trusting a separately-supplied string,
matching the fix already applied to the 11 sibling workflows. **Regression test**:
`ai12WorkflowEdgeCases.test.ts` › `"malformed/missing period.horizon.reached payload degrades to
the current period instead of throwing"` — asserts an empty payload and a garbage
`{period, periodEnd}` pair both complete without `status: "failed"` and default to the current
calendar month. All 19 of AI-12's existing tests (unit + edge-case) re-run clean after the fix.

**Everything else in `lib/aiRuntime/workflows/ai-12-tax-intelligence/index.ts` was checked and
found correct** — its tenant scoping, null-handling, and precision/rounding held up under
inspection and adversarial testing before this one gap was found.

**Honest gap named, not fixed**: concurrent/simultaneous duplicate `period.horizon.reached`
dispatch was not tested under genuine `Promise.all` concurrency for AI-12 specifically (see C.3
above) — repeated-call idempotency is proven, true concurrent-call idempotency is inferred from
the rebuild's delete-and-replace design but not independently exercised the way AI-09/AI-10's
concurrent tests were built. Low risk (the design argument is sound: a period-scoped
delete-and-replace has no per-item collision window the way a per-schedule-period draft does), but
named rather than silently assumed equivalent.

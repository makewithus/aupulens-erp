## Addendum B update (2026-09-12) — re-run against the full `SOURCE-SPEC.md`, not fragments

The complete CTO document arrived with Addendum B. Rows below are corrected against the literal
text where it moved something; rows not listed here were checked and found to already match.

- **§5 — Create Organisation.** PARTIAL, more precisely than before. System-generated fields
  (Organisation ID, Tenant ID, Created At, Created By, Initial Status) are all correct. Currency
  and Timezone ARE captured, but derived from Country via `lib/constants/countries.ts` rather than
  asked for independently — a legitimate pre-existing pattern (single source of truth so an admin
  doesn't have to separately pick a timezone for "India"), not a gap. **Real gaps**: no separate
  "Legal Name" vs. "Display Name" fields (one `name` field serves both); no **Tax Jurisdiction**
  field anywhere; **no Subscription Plan selection at creation time** — a plan must be assigned as
  a separate step afterward via the Subscription tab, not as part of the create form the spec
  describes. The last one is the most visible: an admin creating an organisation today cannot set
  its plan in the same flow §5 describes.
- **§8 / §11 — plan management / custom plans.** Per Addendum B Part 1, `PLAN_KEY` stays a fixed
  7-value enum — the spec's "create a custom plan for enterprise customers" (§11) is satisfied by
  `CUSTOM` as a base plan plus the `OrganizationEntitlement` override layer (Group A item 3), not
  by free-form plan-key creation. Documented, not re-opened.
- **§13 — AI usage dashboard, 13 named metrics.** Re-counted precisely against the literal list:
  10 of 13 present (This Month, Today, Previous Month, Input/Output Tokens, Estimated Cost, Top
  Organisations, Top AI Features, Failed Requests, Average Request Cost). **3 genuinely missing**:
  an all-time **Total AI Requests** figure (distinct from "this month," which is all that's
  currently shown), a combined **Total Tokens** figure (input+output currently shown separately,
  trivial to add), and **Top Models** — grouping by the actual model name (`gpt-4o` etc.), which
  is a completely different missing metric from "Top Features" (a pre-existing internal variable
  in `lib/platform/ai/dashboard.ts` was even misleadingly named `byModel` while actually grouping
  by feature — a naming bug, not a duplicate implementation). Top Models is non-trivial to add
  cleanly: the `AiUsageMonthly`/`AiUsageDaily` rollups this dashboard deliberately reads instead of
  raw records (a documented performance design choice) don't carry a `modelName` field at all —
  see Group B for the resolution.
- **§20 — organisation-type log profiles.** Re-scoped, not a straightforward match. The spec's
  literal per-type lists (SME: "Accounting, Sales, Purchase, Inventory, Tax, AI, Users") are
  **tenant module names**, describing which of a tenant's own modules are relevant to log for that
  business type. What was built (`OrganizationType.logProfile.eventCategories`) instead filters by
  **platform audit event category** (ADMIN, ORGANIZATION, SUBSCRIPTION, AI, SECURITY, etc.) — a
  different, and real, axis (which *kinds of platform-level events* matter for this org type), but
  not the same thing the spec's worked example describes (which *tenant modules* matter). Marked
  PARTIAL: the mechanism is real and correctly a display filter only (never a restriction on what's
  logged), but doesn't implement the literal per-type module-relevance lists from the spec.
- **§28 — 10 named alert conditions.** Only 2 of 10 are wired: "organisation exceeded AI quota"
  (`AI_USAGE_THRESHOLD`) and "organisation suspended" (`ORGANIZATION_SUSPENDED`). Re-triaged
  against real data availability in Group C/D:
  - **Buildable from data this project already has** (not yet built): multiple failed admin
    logins (from `AdminSession`/login-attempt tracking), large subscription downgrade (from
    `SubscriptionEvent`, comparing tier/plan rank), repeated permission failures (from
    `PlatformAuditLog`'s existing `CROSS_TENANT_READ_DENIED`/`AdminForbiddenError` denial audits —
    the data is already captured, just not aggregated into an alert), AI cost spike (a
    month-over-month or day-over-day cost delta heuristic on the same rollups §13 reads).
  - **DECLARED_NOT_POSSIBLE, real reasons**: payment failure (no payment gateway integration
    exists anywhere in this codebase), unusual API usage (§29's own finding: no external API
    traffic exists to be "unusual" against), mass data export (no data-export feature exists in
    this control plane to monitor in the first place), system error spike (no general
